## Push

Firebase Cloud Messaging (D-19), same mechanism as `customer_app`. Each flavor
reads `android/app/src/<flavor>/google-services.json` (private, gitignored).
Place it with:

```bash
rider_app/tool/setup_firebase.sh --copy                # dev (Firebase project jivo-quick, app in.jivo.rider.dev)
rider_app/tool/setup_firebase.sh --copy --env staging  # when that project exists
rider_app/tool/setup_firebase.sh --remove              # back to push off
```

The script copies from `~/.config/jivo-quick-commerce/firebase/<env>/`, checks
that the file registers the flavor's package and prints file names only. The
Gradle build applies the google-services plugin only when a flavor has its
file. Without it the app builds and runs with push off (`NoopPushMessaging`);
offers still arrive on the rider socket and by polling. Behaviour (channels,
background offer alarm, taps, token lifecycle): `docs/04-rider-app.md` §5
"Push".

## Brand: launcher icon, splash and logo

Built from Jivo's official logos (2026-11-23, `design/incoming/brand-2026-11-23/`,
gitignored): the white Jivo face on the brand green `#2D5528`, plus a small
"RIDER" pill so the app is easy to tell from the customer app.

- Adaptive icon (all devices, minSdk 26): `mipmap-anydpi-v26/ic_launcher.xml`
  (foreground and monochrome = `drawable-*dpi/ic_launcher_foreground.png`),
  `values/ic_launcher_colors.xml`. Legacy fallback: `mipmap-*/ic_launcher.png`.
- Splash: Android 12+ `values-v31`/`values-night-v31` styles; older Android
  `drawable*/launch_background.xml` with `drawable-*dpi/splash_logo.png`.
- In-app wordmark: `assets/brand/jivo_wordmark.png` via `JivoWordmark`
  (`lib/shared/widgets/jivo_wordmark.dart`).

All PNGs are generated by
`uv run --with pillow python tool/gen_brand_assets.py <brand folder>`.
The status-bar icon `drawable/ic_stat_rider.xml` is still the placeholder.
