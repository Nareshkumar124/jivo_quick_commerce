Django project: `backend/`. Each business area is a Django app under `backend/apps/`.
The **OpenAPI schema** (`/api/schema/`, generated by drf-spectacular) is the source of truth for request/response shapes. This document lists endpoints and their purpose.

### 1.1 Service-layer rule
Business logic lives in **service modules** (`apps/<app>/services.py`), not in views or serializers. Example: `orders.services.place_order(...)`, `orders.services.transition(order, to_status, actor)`, `inventory.services.reserve(...)`, `delivery.services.dispatch(order)`. Views stay thin, and services are unit-tested directly. State transitions **only** happen through `orders.services.transition()`, which validates against the state machine in [08-order-lifecycle.md](08-order-lifecycle.md), writes `OrderStatusHistory` and emits events.

### 1.2 Domain events
Services emit internal events (e.g., `order_placed`, `order_status_changed`, `task_assigned`). Handlers, run with `transaction.on_commit` and dispatched to Celery, send notifications, push WebSocket messages and start dispatch. This keeps side effects out of the core transaction and retryable.

### 2.1 Auth & account [P1]
| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| POST | `/api/v1/auth/otp/request/` | Public | Send OTP to `phone` for `app` (`customer`/`rider`). Rate-limited. |
| POST | `/api/v1/auth/otp/verify/` | Public | Verify OTP. Returns `access`, `refresh`, `user`, `is_new_user` (+ `rider_status` for the rider app). |
| POST | `/api/v1/auth/token/refresh/` | Public | Rotate the refresh token |
| POST | `/api/v1/auth/logout/` | Customer | Blacklist the refresh token, deactivate the device |
| GET / PATCH | `/api/v1/me/` | Customer | Read / update name, email, notification prefs |
| POST | `/api/v1/me/delete/` | Customer | Request account deletion (requires a fresh OTP) |
| POST | `/api/v1/me/devices/` | Customer | Register/update the FCM token, platform, app, version |
| GET | `/api/v1/config/app/` | Public | `min_supported_version`, `latest_version`, `maintenance`, support contacts, policy URLs, feature flags |

Contract details (published in `backend/openapi/schema.yaml`, Phase 1 R1; the schema has request/response examples for every case):
- **operationIds:** `auth_otp_request`, `auth_otp_verify`, `auth_token_refresh`, `auth_logout`, `me_retrieve`, `me_update` (PATCH), `me_delete_account`, `me_device_register`, `config_app`.
- **Enums:** `app` = `customer`/`rider` (same as `X-App-Name`), `platform` = `android`/`ios` (same as `X-Platform`), OTP `purpose` = `login`/`delete_account`, `rider_status` = `NONE`/`PENDING_KYC`/`ACTIVE`/`REJECTED`/`SUSPENDED` (07 §2.8 statuses plus `NONE` = no rider profile).
- **OTP request** `{phone, app, purpose?}`: `phone` is an Indian mobile in E.164 (`+91[6-9]XXXXXXXXX`). Response `{otp_length, expires_in_seconds, resend_after_seconds}`, identical whether or not the phone has an account. Rate limits answer 429 `OTP_RATE_LIMITED` with `details.retry_after_seconds` and `Retry-After` (never the generic `RATE_LIMITED`).
- **OTP verify** `{phone, otp, app, terms_version}`: the body `app` must match the OTP's app and is authoritative over `X-App-Name`. `terms_version` (from `config/app`) is stored on the user with the acceptance time whenever it changes (DPDP consent, added in Phase 1 R2). Response `{access, refresh, user, is_new_user, rider_status, deletion_cancelled}`. Logging in during the 30-day deletion grace period **restores** the account and returns `deletion_cancelled: true`; after anonymisation the phone signs up as a new user. `rider_status` is **always present** (`NONE` until Phase 5 adds rider profiles); the customer app ignores it. `is_new_user` = this verification created the account; show complete-profile when `is_new_user` or `!user.is_profile_complete`. Wrong code: 400 `OTP_INVALID` with `details.attempts_remaining`; expired, used or out of attempts (5): 400 `OTP_EXPIRED`; deactivated account: 403 `PERMISSION_DENIED`. A `delete_account` OTP never signs in.
- **Token refresh** `{refresh}` → `{access, refresh}`. The old refresh token is revoked on use. Only 401 `TOKEN_INVALID` ends the session; this endpoint is exempt from 426/503.
- **Logout** `{refresh, fcm_token?}` → 204, idempotent (already revoked or foreign tokens are ignored).
- **Me**: `{id, phone, name, email, marketing_opt_in, is_profile_complete, rider_status, created_at}`. PATCH accepts `name` (not blankable), `email` (published as one nullable `string`/`email` since Phase 1 R3, without the `oneOf` the Dart generator could not handle; unique, null or "" clears; a conflict answers `VALIDATION_ERROR` with the generic "This email can't be used." so other accounts are not revealed), `marketing_opt_in`. `phone` is read-only in v1.
- **Account deletion** (fresh OTP): `POST /auth/otp/request/` with the caller's phone and `purpose: delete_account`, then `POST /me/delete/ {otp, reason?}`. Only a `delete_account` OTP issued to the caller's phone is accepted. Response `{deleted_at, anonymise_after}` (30-day grace, 07 §4); all refresh tokens are revoked, access tokens stop working and devices are deactivated. Staff accounts get 403 `PERMISSION_DENIED` (deleted by an administrator).
- **Devices**: `POST /me/devices/ {fcm_token, app, platform, app_version}` is an upsert keyed on `fcm_token` (moves to the caller if registered to someone else); always 200.
- **Config** `GET /config/app/`: versions and `store_url` are for the `X-App-Name` + `X-Platform` of the request (null without those headers), plus `maintenance`, `maintenance_message`, `support {phone, email}`, `policy_urls {terms, privacy, refund}`, `terms_version`, `otp {length, resend_after_seconds}`, `rider_location {active_interval_seconds, idle_interval_seconds}` (04 §3) and `feature_flags` (name → bool; ignore unknown keys).
- **Redis outage (09 §2):** `config/app` and the 426/503 guard fall back to the database when the cache is down. OTP rate limiting is **fail-closed**: `otp/request`, `otp/verify` and `me/delete` answer 503 `SERVICE_UNAVAILABLE` ("Sign-in is temporarily unavailable…") instead of sending or checking OTPs without counters. Fixed-OTP test numbers skip the counters and keep working.
- **426 / 503 on app endpoints:** every `/api/v1/` endpoint except `config/app` and `auth/token/refresh` can answer 426 `APP_UPDATE_REQUIRED` (`details: {min_supported_version, latest_version, store_url}`) and 503 `MAINTENANCE`. 426 is sent only when `X-App-Name`, `X-Platform` and `X-App-Version` are all present and the version is below the minimum; requests without them never get 426.

### 2.2 Addresses [P1]
| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| GET / POST | `/api/v1/addresses/` | Customer | List / create (includes `lat`, `lng`) |

Contract details: operationIds `addresses_list`, `addresses_create`, `addresses_retrieve`, `addresses_update` (PATCH; no PUT), `addresses_delete`, `addresses_set_default`. The list is paginated per 02 §5 (default first, then newest). `label` = `home`/`work`/`other` plus optional `custom_label`. `lat`/`lng` are JSON numbers and **required** (03 §2.4: the map pin is required). `receiver_name`/`receiver_phone` default to the user's own. `is_default` is read-only: the first address becomes the default, `set-default` moves it, and deleting the default promotes the most recently updated remaining address. Another user's address id answers 404 `NOT_FOUND`.

Rules for the envelope (implemented in `apps.core.exceptions`, codes in `apps.core.errors.ErrorCode`, published as `ErrorCodeEnum` / `ErrorEnvelope` in the OpenAPI schema; the inner `error` object is the component `ErrorBody`, renamed from `ApiError` in Phase 1 R3 because it clashed with `jivo_core`'s `ApiError`; the JSON shape did not change):
- `details` is always an object, possibly empty. `VALIDATION_ERROR` puts field name → list of messages there, with `non_field_errors` for errors that are not about a field. Malformed JSON is also `VALIDATION_ERROR`.
- `401`: `AUTH_REQUIRED` when no credentials are sent, `TOKEN_INVALID` for a bad, expired or revoked token (or an inactive user).
- Django's `Http404` / `PermissionDenied` / `ValidationError` map to `NOT_FOUND` / `PERMISSION_DENIED` / `VALIDATION_ERROR`. Unmatched `/api/...` URLs also return the JSON envelope.
- Codes are a stable contract: add new ones, never rename or remove.
