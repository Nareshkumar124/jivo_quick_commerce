# BUG-0004: `addresses_list` returns 404 for an invalid page, but the contract doesn't document it

| Field | Value |
|---|---|
| Bug ID | BUG-0004 |
| Module | backend: OpenAPI contract `backend/openapi/schema.yaml` (`GET /api/v1/addresses/`) and `apps/accounts/views.py` `AddressListCreateView.get` |
| Owner agent | `django-backend-dev` |
| Severity | **P3 Minor** (brief scale: **Low**). Contract gap; no functional break for the current apps. |
| Priority | P3 |
| Status | Open |
| Found | 2026-11-02, QA run 1 (schemathesis status-code conformance) |
| Environment | Commit `4960527`, QA instance `127.0.0.1:8004` |
| Tests | `test_p1_addresses.py::test_p1_tc48_list_pagination_and_order` (asserts the 404, passes); `test_fuzz_schemathesis.py` (ST103 "Undocumented status code") |

## Steps to reproduce
`GET /api/v1/addresses/?page=0`, `?page=99` (past the end) or `?page=abc`, with a valid customer token.

## Expected
Every status code the endpoint can return is listed in the OpenAPI operation, as 02 §5 requires: "the schema is the source of truth for request/response shapes". 06 §2.2 says the list is paginated per 02 §5. `apps/core/pagination.py` documents "An out-of-range page returns 404 NOT_FOUND". So `addresses_list` should list `404` with the `ErrorEnvelope` schema, or treat invalid pages differently.

## Actual
```
GET /api/v1/addresses/?page=0 -> 404 {"error":{"code":"NOT_FOUND","message":"Invalid page.","details":{}}}
```
The `addresses_list` operation in `schema.yaml` documents only `200, 401, 426, 503`. Generated clients (`packages/jivo_api`) therefore have no typed 404 for this call.

## Possible root cause
The `@extend_schema(... responses=app_responses({200: ..., 401: UNAUTHORIZED}))` on `AddressListCreateView.get` omits `404`.

## Suggested resolution
Add `404: NOT_FOUND` ("Invalid page") to `addresses_list`, and to every paginated list in later phases, using one shared helper so new list endpoints get it automatically. Then re-export the schema.
