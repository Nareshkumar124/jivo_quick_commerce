## Steps to reproduce
1. Only R1 (+919000000103) is online at QA-02 (R2 offline).
2. QA customer A (+919000000101) places a COD order at QA-02; it is auto-accepted and R1 gets an offer (30 s).
3. R1 does not answer. Wait until the expiry has been processed by the server (the countdown task `expire_offer` at `expires_at`, or the 15 s `dispatch-sweep`): the offer row is `EXPIRED` and the task is back to `SEARCHING` (no other free rider).
4. R1 taps accept: `POST /api/v1/rider/offers/<offer id>/accept/`.

## Expected
- 08 §5 step 4: "A late accept after expiry returns `OFFER_EXPIRED`."
- 06 §3 (5.3 notes): "A late accept is 409 `OFFER_EXPIRED` (the expiry is kept and the next rider is tried). A withdrawn or cancelled offer is 409 `OFFER_TAKEN`."
- The service's own docstring: "Late: 409 OFFER_EXPIRED …; the order went elsewhere or was cancelled: 409 OFFER_TAKEN."

So: `409 {"error": {"code": "OFFER_EXPIRED", …}}`.

## Actual
`409 {"error":{"code":"OFFER_TAKEN","message":"The offer was taken by another rider.","details":{}}}`.

Every trial kept the invariants (one outcome; never ASSIGNED with an EXPIRED offer; at most one PENDING offer). Only the code of the 9 late accepts is wrong. With a second free rider the task is OFFERED again before the late accept arrives, and the code is then correct (P5-TC-41 passes for that reason).

## Possible root cause
`apps/delivery/services/dispatch.py` `accept_offer`, line 390:
```python
if offer.status == OfferStatus.WITHDRAWN or task.status != TS.OFFERED:
    raise ApiError(ErrorCode.OFFER_TAKEN)
if offer.status != OfferStatus.PENDING:
    raise ApiError(ErrorCode.OFFER_EXPIRED)
```
`expire_offer` sets the offer to EXPIRED **and** the task to SEARCHING. When no other rider is offered meanwhile, the task is not OFFERED, so the first check answers OFFER_TAKEN before the EXPIRED check is reached. The backend tests cover only the two other paths: expiry detected by the accept itself (offer still PENDING) and expiry followed by an offer to a second rider (task OFFERED again), which is why they pass (`test_dispatch.py` `test_late_accept_is_offer_expired_and_redispatches`, `test_two_riders_one_order`).

## Suggested resolution
Check the offer's own status first: `EXPIRED` → `OFFER_EXPIRED`; `WITHDRAWN` (or the task taken by another rider / cancelled) → `OFFER_TAKEN`. Add a backend test: one rider, `expire_offer` processed, task SEARCHING (and one with UNASSIGNED), then accept → 409 OFFER_EXPIRED. QA will re-run P5-TC-42 and P5-TC-42b.
