# BUG-0020: An oversized socket message closes with 1011 (server error) instead of 1009 on the dev server

| Field | Value |
|---|---|
| Bug ID | BUG-0020 |
| Module | backend: realtime consumers (`apps/realtime/consumers.py` `receive`, `apps/realtime/contract.py` `CLOSE_MESSAGE_TOO_BIG`) |
| Owner agent | `django-backend-dev` |
| Severity | **P3 Minor** (brief scale: **Low**). The size limit still holds: the socket is closed and the message is never processed. The close code contradicts 06 §4.1, and every oversized message logs an ERROR traceback. |
| Priority | P2 |
| Status | Open |
| Found | 2026-11-06, QA Phase 6 stage 1 (T-611) |
| Environment | develop `8f87d7b`, QA instance `127.0.0.1:8004` (`runserver`, which is daphne 4.2.3 through `INSTALLED_APPS`), `config.settings.local` |
| Test | `qa/tests/test_p6_ws.py::test_p6_tc50_message_over_4096_bytes_1009[before_auth]` and `[after_auth]` |

## Steps to reproduce
1. Open `ws://127.0.0.1:8004/ws/v1/orders/<own order id>/` as QA customer A (+919000000101).
2. Optionally authenticate with `{"type":"auth","token":"<access>"}` (both variants fail the same way).
3. Send one text message of about 5,000 bytes, e.g. `{"type":"ping","pad":"xxxx…"}`.

## Expected
06 §4.1, close codes: "1009: an inbound message over `WS_MAX_MESSAGE_BYTES` (4096)".

## Actual
The client receives close code **1011** (internal error), not 1009. The instance log shows the application raising while it closes:
```
2026-11-06 16:11:00,346 ERROR daphne.server Exception inside application: invalid close code 1009 (must be 1000 or from [3000, 4999])
...
Exception: invalid close code 1009 (must be 1000 or from [3000, 4999])
```
Test output (`qa/private/runs/p6-t611-run1.txt`):
```
FAILED tests/test_p6_ws.py::test_p6_tc50_message_over_4096_bytes_1009[before_auth] - AssertionError: 1011
FAILED tests/test_p6_ws.py::test_p6_tc50_message_over_4096_bytes_1009[after_auth] - AssertionError: 1011
```

## Possible root cause
`receive()` (consumers.py line 146) calls `close_with(contract.CLOSE_MESSAGE_TOO_BIG)` = 1009. daphne's WebSocket stack (autobahn) lets an application close only with 1000 or 3000–4999, so `close(code=1009)` raises, and daphne turns it into 1011 with an ERROR log. The backend's own tests use Channels' `WebsocketCommunicator`, which does not enforce this, so they pass. Staging and production run uvicorn (`backend/Dockerfile`), which QA has not yet verified for this code; the dev server on :8001, which the apps use, is affected.

## Suggested resolution
Use an application code in the 4000 range for "message too big" (for example 4413, documented in 06 §4.1 and `contract.CLOSE_CODES`), which every ASGI server accepts. Otherwise, confirm that 1009 works on uvicorn and document that daphne dev sends 1011. Add a test that runs the close through a real server, or one that asserts the code is 1000 or 3000–4999.
