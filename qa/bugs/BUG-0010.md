# BUG-0010: The panel has no manual refund (full / partial) for Super Admin, Support and Finance

| Field | Value |
|---|---|
| Bug ID | BUG-0010 |
| Module | admin panel: Orders admin (`apps/orders/admin.py` `OrderAdmin`), Refunds admin (`apps/payments/admin.py`), Ops Console |
| Owner agent | `admin-panel-dev` (the service `apps.payments.order_refunds.manual_refund` exists, backend) |
| Severity | **P2 Major** (brief scale: **Medium**). A P4 feature in 05 §2 / §3 is missing: staff cannot issue a goodwill or partial refund from the panel. No money is at risk (nothing wrong happens; the action is just absent). |
| Priority | P1 (it blocks P4-TC-32/33 through the console and the 05 §3 "Refund" row) |
| Status | Open |
| Found | 2026-11-04, QA Phase 4 stage 2 |
| Environment | `qa/phase-2` at `f744508` (develop `ef1426a`, admin P4 T-413 merged), QA instance `127.0.0.1:8004` (local settings), shared remote DB |
| Test | `qa/tests/test_p4_console.py::test_p4_tc32c_manual_refund_in_panel`, `::test_p4_tc40_orders_admin` (both `xfail(strict=True)`) |

## Steps to reproduce
1. Log in to `/admin/` as Super Admin, Support or Finance (seeded accounts).
2. Open `/admin/orders/order/` and the change page of a paid ONLINE QA order (e.g. `/admin/orders/order/<id>/change/`).
3. Look for a refund action (list actions, object actions, buttons) there, on `/admin/payments/refund/` and in the Ops Console.

## Expected
- 05 §2 "Orders" (P4): "Actions: cancel, **refund (full/partial, within role limit)**, resend invoice, export CSV."
- 05 §3 "Refund": Super Admin ✔, Support ✔ up to ₹500, Finance ✔.
- 05 §2 (Phase 4 permissions note): the screens call `apps.payments.order_refunds` (`manual_refund`, `retry_refund`).

## Actual
- `OrderAdmin.get_actions()` returns `{}` and the change page has no refund form or button (only links to the Refunds list).
- The Refunds admin has only "Retry failed refund".
- `apps/ops_console/once.py` defines `MANUAL_REFUND = "manual-refund"`, but nothing uses it; `grep manual_refund` finds only the service.
- Probe output (Super, Support, Finance; order detail, order list, refund list): `found = [False, False, False]`.

## Possible root cause
The manual refund screen was not built in T-413 (the retry screen and its one-time token were).

## Suggested resolution
An object action on the order (or the Ops Console order view) with an amount field (prefilled with what is refundable, full or partial) and a note, shown to roles with `payments.issue_refund`; post it with a `once` token (`MANUAL_REFUND`) and call `order_refunds.manual_refund(order_id, amount, by=request.user, note=...)`; map `ValidationError` (limit, cap "At most …", not paid) to form errors. The service already enforces the Support ₹500 limit, the cap and the audit row (verified at service level in P4-TC-32/33).
