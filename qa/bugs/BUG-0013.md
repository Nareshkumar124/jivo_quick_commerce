# BUG-0013: A user with no rider profile gets 400 instead of 403 on documents and bank-account when the body is invalid

| Field | Value |
|---|---|
| Bug ID | BUG-0013 |
| Module | backend: rider API (`POST /api/v1/rider/documents/`, `PUT /api/v1/rider/bank-account/`) |
| Owner agent | `django-backend-dev` |
| Severity | **P3 Minor** (brief scale: **Low**). No data is exposed or changed. The error contract and the order of checks are wrong. |
| Priority | P3 |
| Status | Open |
| Found | 2026-11-06, QA Phase 5 stage 2 |
| Environment | develop `680b904` (identical backend API to `f5d39ff`), QA instance `127.0.0.1:8004` |
| Test | `qa/tests/test_p5_kyc.py::test_p5_tc16_no_profile_invalid_body_still_403` (`xfail(strict=True)`) |

## Steps to reproduce
1. Log in, through the rider app, as a user with no rider profile (QA user E, +919000000105, OTP 123456).
2. `PUT /api/v1/rider/bank-account/` with body `{}`.
3. `POST /api/v1/rider/documents/` (multipart) with `doc_type=PAN` and a PNG file, without `number`.

## Expected
06 §3 "Access": "every rider operation except stores and register needs a rider profile, else 403 `PERMISSION_DENIED` with `details.rider_status` = NONE". With a valid body, both endpoints do return this 403.

## Actual
```
PUT /api/v1/rider/bank-account/ -> 400 {"error":{"code":"VALIDATION_ERROR","message":"Some fields are invalid.","details":{"holder_name":["This field is required."],"account_number":["This field is required."],"ifsc":["This field is required."]}}}
POST /api/v1/rider/documents/ -> 400 {"error":{"code":"VALIDATION_ERROR",...,"details":{"number":["Enter the document number."]}}}
```

## Possible root cause
The views validate the serializer before calling `riders.require_rider(user)`.

## Suggested resolution
Check the rider profile first (a permission class or `require_rider` at the top of the view), then validate the body. Add a test that pairs no profile with an invalid body.
