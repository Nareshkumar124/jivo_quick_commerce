| Field | Value |
|---|---|
| Bug ID | BUG-0024 |

| Owner agent | `admin-panel-dev` |
| Severity | **P2 Major** (brief scale: **Medium**). A role that DL-61 (a) allows to do an ops delivery action cannot do it in the panel. Workaround: Super Admin or Ops sets the limit. No security, money or stock impact: the refusal is too strict, not too loose. |

## Steps to reproduce
1. Sign in to `/admin/` as the QA-only Store Manager of QA-02, `qa02.manager@jivo.test` (Store Manager group, QA-02 access only).
2. Open rider R1 (QA number +919000000103, home store QA-02): `GET /admin/delivery/rider/<R1 id>/cash-limit/`.

## Expected
- DL-61 (a) (decision log, user decision 2026-11-05): "Super Admin and Ops/Dispatch get every ops delivery action: … set cash limit. **Store Manager gets them for their own store only.**"
- The backend service agrees: `apps/delivery/services/kyc.py` `set_cash_limit` docstring "DL-61 (a): Super Admin, Ops, Store Manager (riders of their own stores)" and it checks `delivery.dispatch_order` + home store in the user's stores.
- So the QA-02 Store Manager gets the cash-limit form for R1 and can save it (an audit row `rider.cash_limit` with their user id).

## Actual
`403` (Django admin permission denied) for the QA-02 Store Manager. In the same run, as the matrix expects: Super Admin and Ops get the form and save it (302); the GGN-01 Store Manager gets 403/404 (not his store); Finance, Support, Store Staff and Catalog get 403. Force offline (`/ops/dispatch/riders/<id>/offline/`) works for the QA-02 Store Manager (302, R1 offline), so only the cash limit is affected.

Evidence:
```
# P5-TC-117, qa/private/runs/s4-p5-batch2-run1.txt
E   AssertionError: ('qa02.manager@jivo.test', 302, False, 403)      # (force offline, R1 online after, cash-limit page)

# The service itself allows it (QA driver, as the same user, read back from the DB):
set_cash_limit as qa02.manager@jivo.test on R1 -> {'ok': True}  cash_limit 5000.00
set_cash_limit as store.manager@jivo.test (GGN-01) on R1 -> {'ok': False, 'error': 'ValidationError', 'message': 'Rider not found.'}

# Store Manager group permissions (read-only SQL): view_rider, dispatch_order; no review_rider
```

## Possible root cause
`backend/apps/delivery/admin.py`:
- line 270 `has_cash_limit_permission` correctly uses `kyc.OPS_DELIVERY` (`delivery.dispatch_order`), so the action is offered;
- but the action body calls `self._rider(request, object_id)` (line 280), which first does `if not kyc.can_review(request.user): raise PermissionDenied`. `can_review` needs `delivery.review_rider`, which only the KYC reviewers (Super Admin, Ops) hold. So every Store Manager is refused before the service is called.

## Suggested resolution
Give `change_cash_limit` its own lookup: require `kyc.OPS_DELIVERY` and fetch the rider from `Rider.objects.filter(home_store__in=stores_for(user))` (an id outside it → 404), then call `kyc.set_cash_limit`, which re-checks the same rule. Keep `_rider()` (review permission) for approve / reject / suspend / reinstate / home store. Add an admin test: Store Manager of the rider's home store → 200 form and 302 save with an audit row; Store Manager of another store → 404. QA will re-run P5-TC-117.
