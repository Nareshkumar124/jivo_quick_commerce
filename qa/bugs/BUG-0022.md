# BUG-0022: `rider.location` always carries `heading: null`, although the rider app sends a heading

| Field | Value |
|---|---|
| Bug ID | BUG-0022 |
| Module | backend: rider location ingest (`apps/delivery/services/shifts.py` `ingest_locations`) |
| Owner agent | `django-backend-dev` |
| Severity | **P3 Minor** (brief scale: **Low**). Position, gate, scoping and ETA are all correct. Only the direction field is lost, so the customer and ops maps cannot orient the rider marker. |
| Priority | P3 |
| Status | Open |
| Found | 2026-11-10, QA stage 3 (P6, T-612 suite) |
| Environment | QA instance `127.0.0.1:8004` (`config.settings.local`), QA worker on Redis DB 7, shared dev DB. Build: develop `efb3c3d` (QA worktree `b87eb5f`). Code unchanged on develop `3f6fc42`. |
| Test | `qa/tests/test_p6_t612.py::test_p6_tc14_tc15_tc16_location_gate_eta_and_scope` (P6-TC-14) |

## Steps to reproduce
1. R1 (+919000000103) holds an ASSIGNED task for customer A's order at QA-02. A has the order socket open and authorised.
2. R1: `POST /api/v1/rider/locations/ {"points": [{"lat": 26.9127597, "lng": <lng>, "accuracy": 10, "heading": 72.5, "recorded_at": "<now>"}]}` → 200 `accepted: 1`.
3. Read the `rider.location` message on A's socket (the ops feed shows the same).

## Expected
06 §3 (`/rider/locations/`): points carry `heading?`. 06 §4.2 example: `{"type": "rider.location", "data": {"order_id": 1203, "lat": 28.4741, "lng": 77.0489, "heading": 72.5, "recorded_at": "…"}}`. The contract field is "Degrees from north, or null" (`apps/realtime/contract.py`), so `heading` should be 72.5.

## Actual
`heading` is `null` (order 775 in run 3; 747 in run 1). Test output (`qa/private/runs/s3-p6-t612-run3.txt`):
```
E   assert (775 == 775 and 0.0 < 1e-06 and None == 72.5)
E    +  where 0.0 = abs((26.9127597 - 26.9127597))
```
The order id and the latitude match exactly; only `heading` is None. The point itself is stored with its heading (`RiderLocation.heading`, `shifts.py` line 287).

## Possible root cause
`apps/delivery/services/shifts.py` lines 315–317:
```python
lambda: hooks.publish_rider_location(
    rider.pk, latest["lat"], latest["lng"], latest_at
)
```
`hooks.publish_rider_location(..., *, heading=None)` (`apps/delivery/hooks.py` line 65) is never given `heading=latest.get("heading")`, so `realtime.publish_rider_location` always sends None.

## Suggested resolution
Pass `heading=latest.get("heading")` in that call (and in `_remember_location` if the cached latest location should keep it). Add a backend test asserting that the published `rider.location` keeps the point's heading.
