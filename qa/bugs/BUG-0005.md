# BUG-0005: Production settings silently default to the console SMS backend, which logs OTP codes

| Field | Value |
|---|---|
| Bug ID | BUG-0005 |
| Module | backend: `config/settings/base.py` (`SMS_BACKEND`), `apps/notifications/sms.py`, `apps/accounts/checks.py` |
| Owner agent | `django-backend-dev` |
| Severity | **P3 Minor** (brief scale: **Low**). Hardening: production is not live, and the real gateway (D-02) is not chosen yet. |
| Priority | P2 (must be closed before any deployed environment uses real phones) |
| Status | Open |
| Found | 2026-11-02, QA run 1 (configuration review plus `check --deploy`) |
| Environment | Commit `4960527`. `config.settings.production` loaded with a throwaway secret key, `DJANGO_ALLOWED_HOSTS=api.example.test` and `NUM_PROXIES=1`. No DB access. |

## Steps to reproduce
1. With production settings and no `SMS_BACKEND` env var, inspect the settings: `SMS_BACKEND = apps.notifications.sms.ConsoleSmsBackend`.
2. Run `manage.py check --deploy --fail-level WARNING`: "System check identified no issues".
3. `ConsoleSmsBackend.send()` (`apps/notifications/sms.py`, around lines 37–45) logs the full SMS body at WARNING level: "SMS (console backend) to +91******3210 … : <#> 123456 is your Jivo verification code …".

## Expected
09 §3.3: "PII is minimised in logs". 09 §3.1: OTPs are stored hashed, never plain. 09 §3.3 and 10 §2 also require `check --deploy` in CI for production settings. Following those, a deployed environment should refuse to start, or fail a system check, when the SMS backend is the console or locmem backend. That way OTP codes can never reach production logs or Sentry, and a missing gateway configuration fails loudly instead of silently sending nothing.

## Actual
Production loads the console backend by default, with no warning or error. Every OTP in production would be written in plain text to the application log, and no SMS would be sent.

## Evidence
```
production settings dump: DEBUG False SMS_BACKEND apps.notifications.sms.ConsoleSmsBackend ... OTP_TEST_NUMBERS {} SEED_DEMO_ALLOWED False
$ manage.py check --deploy --fail-level WARNING -> System check identified no issues (0 silenced).
```
(`qa/private/runs/deploy-checks-4960527.txt`)

## Possible root cause
`config/settings/base.py`: `SMS_BACKEND = env_str("SMS_BACKEND", default="apps.notifications.sms.ConsoleSmsBackend")`. Neither `config/settings/deployed.py` nor `production.py` overrides it or requires it, and `apps/accounts/checks.py` checks only `OTP_TEST_NUMBERS`.

## Suggested resolution
In `deployed.py` (or `production.py`), require `SMS_BACKEND` from the environment with no default. Also add a system check (`accounts.E003`) that fails when `APP_ENVIRONMENT in ("staging", "production")` and the backend is `ConsoleSmsBackend` or `LocmemSmsBackend`. Staging may allow it explicitly behind a flag until D-02 is decided.
